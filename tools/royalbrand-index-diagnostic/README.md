# عیب‌یاب موقت ایندکس رویال‌برند — فقط خط فرمان

این ابزار کمک می‌کند پاسخ فنی سه صفحه زیر، **از داخل همان هاست**، بررسی شود:

1. `https://royalbrand.vip/services/`
2. `https://royalbrand.vip/services/کمپین-برندینگ/`
3. `https://royalbrand.vip/services/کمپین-360-درجه/`

**برای استفاده، فقط فایل [`diagnose.php`](diagnose.php) را روی هاست بگذارید.** فایل‌های `tests.php` و `tests_http.py` مربوط به آزمون توسعه هستند و نیازی به آپلود آنها نیست. افزونه یا نصب وردپرس لازم نیست.

## این ابزار چه می‌کند و چه نمی‌کند؟

- برای هر یک از سه صفحه، یک درخواست با User-Agent مرورگر موبایل و یک درخواست با User-Agent شبیه‌سازی‌شدهٔ Googlebot می‌فرستد؛ **این درخواست دوم خود گوگل نیست و از IP گوگل نمی‌آید**.
- علاوه بر سه صفحه، فقط فایل‌های عمومی `robots.txt`، `page-sitemap.xml` و `sitemap_index.xml` را می‌خواند؛ صفحهٔ چهارمی درخواست نمی‌کند. در حالت بدون ریدایرکت مجموعاً ۹ درخواست HTTP است. حداکثر دو ریدایرکت هر درخواست را فقط وقتی به یکی از همین شش نشانی مجاز و بدون پارامتر برسد دنبال می‌کند؛ ریدایرکت‌های دیگر متوقف و در خروجی گزارش می‌شوند.
- وضعیت HTTP، بخشی از هدرهای مرتبط با ایندکس، canonical، متای robots، تعداد H1، لینک‌های بین همین سه صفحه و حضور در نقشهٔ برگه‌ها را بررسی می‌کند. **تحلیل HTML خام است**؛ جاوااسکریپت را اجرا یا صفحه را رندر نمی‌کند. تحلیل `robots.txt` تقریبی است و فقط نقشه‌های نام‌برده بررسی می‌شوند، نه همه نقشه‌های احتمالی سایت.
- لاگ سرور، پیکربندی وردپرس، پایگاه‌داده و فایل‌های محتوای وردپرس را نمی‌خواند؛ تنظیمات و محتوا را تغییر نمی‌دهد و Request Indexing نمی‌فرستد. خود اسکریپت فایلی نمی‌نویسد؛ فرمان پیشنهادی پایین، خروجی را در یک فایل خصوصی ذخیره می‌کند. درخواست‌ها ممکن است مثل هر بازدیدی در لاگ معمول وب‌سرور ثبت شوند یا بر کش اثر بگذارند.
- درخواست‌ها گواهی HTTPS را بررسی می‌کنند و پراکسی‌های تنظیم‌شده در محیط را دور می‌زنند. اگر هاست دسترسی خروجی یا اتصال به دامنهٔ خودش را محدود کند، نتیجه ممکن است نامشخص باشد؛ این به‌تنهایی خطای دسترسی گوگل نیست.
- خروجی، متن کامل صفحه، کوکی، هدر کامل و پارامتر URL را چاپ نمی‌کند؛ مسیرهای ناشناخته نیز پنهان می‌شوند. **با وجود این، پیش از ارسال، کل فایل را برای دادهٔ حساس بازبینی کنید.**

> **محدودیت مهم:** حتی اگر همه پاسخ‌ها `200` باشند، ابزار نمی‌تواند ثابت کند خزندهٔ واقعی گوگل این صفحات را دیده، canonical آنها را انتخاب کرده یا آنها را ایندکس کرده است. مرجع وضعیت ثبت‌شده همچنان **URL Inspection → Google Index** است. موفقیت Live Test هم تضمین ایندکس نیست.

## پیش‌نیاز و محل امن

- دسترسی **Terminal در cPanel یا SSH** برای اجرای فرمان PHP، PHP نسخهٔ **۷٫۴ یا بالاتر**، و افزونه‌های **cURL** و **DOM** برای همان PHP خط فرمان لازم است. نسخهٔ PHP خط فرمان ممکن است با نسخهٔ وب متفاوت باشد.
- یک پوشهٔ جدید در **Home Directory** حساب هاست بسازید؛ مثلاً `rb-index-diagnostic`. باید **خارج از `public_html`، `www` و هر DocumentRoot قابل‌دسترسی از وب** باشد. اگر ساختار هاست متفاوت است، محل خصوصی را با پشتیبانی هاست تأیید کنید. فایل را در پوشهٔ عمومی سایت، وردپرس یا WPCode قرار ندهید. فایل از طریق مرورگر اجرا نمی‌شود.
- در File Manager هاست، فقط `diagnose.php` را داخل آن پوشهٔ خصوصی آپلود کنید. اگر پوشه‌ای با همین نام از قبل دارید، پوشهٔ تازه‌ای با نام دیگری بسازید و همان نام را در فرمان‌های زیر جایگزین کنید؛ فایل‌های موجود را بازنویسی نکنید.
- اگر Terminal/SSH در دسترس نیست، این روش را از مسیر عمومی اجرا نکنید؛ اطلاع دهید تا راه امن متناسب با دسترسی شما بررسی شود. نیازی به ارسال رمز، دسترسی هاست یا ایجاد کاربر برای این بررسی نیست.

## گام‌های اجرا

در مثال زیر فرض شده پوشهٔ تازه دقیقاً `$HOME/rb-index-diagnostic` است و فایل در آن آپلود شده است. `$HOME` خودکار به پوشهٔ اصلی همان حساب اشاره می‌کند؛ چیزی به‌جای آن ننویسید.

1. در Terminal ابتدا پیش‌نیازها و نحو فایل را بررسی کنید:

```bash
php -v
php -m
php -l "$HOME/rb-index-diagnostic/diagnose.php"
```

در خروجی `php -m`، `curl` و `dom` را پیدا کنید و مطمئن شوید فرمان آخر `No syntax errors detected` می‌دهد. اگر PHP یا یکی از افزونه‌ها موجود نبود یا غیرفعال بود، اجرا را متوقف کنید؛ پشتیبانی می‌تواند نسخه/ماژول **CLI** را مشخص کند. برای این کار تنظیمات امنیتی، TLS، DNS یا robots را تغییر ندهید.

2. خروجی را فقط در پوشهٔ خصوصی ذخیره کنید:

```bash
umask 077
php "$HOME/rb-index-diagnostic/diagnose.php" > "$HOME/rb-index-diagnostic/result.json"
```

این دستور یک فایل `result.json` در همان پوشه می‌سازد؛ `umask` برای همین نشست، فایل جدید را برای دیگر کاربران محدود می‌کند. در شرایط معمول چند لحظه طول می‌کشد، اما به‌خاطر محدودیت ۱۵ ثانیه برای هر درخواست و ریدایرکت‌ها ممکن است چند دقیقه طول بکشد. تا پایان اجرا منتظر بمانید. زمان‌های خروجی UTC و بر اساس ساعت هاست هستند.

3. با File Manager، `result.json` را از همان پوشهٔ خصوصی دانلود و باز کنید. پیش از پیوست‌کردن فایل در همین گفتگو، آن را مرور و هر رمز، توکن، کوکی، شناسهٔ نشست، آدرس خصوصی یا داده‌ای را که نمی‌خواهید به اشتراک بگذارید حذف کنید. **لاگ خام، فایل پیکربندی، URL پنل دارای `cpsess`، نام کاربری/رمز یا کد تأیید ارسال نکنید.** اگر فایل خالی یا خطای مربوط به PHP دیدید، فقط متن خطای پاک‌سازی‌شده و نتیجهٔ `php -v` / نام ماژول‌های لازم را بفرستید.

4. پس از ذخیرهٔ نسخهٔ پاک‌سازی‌شده و ارسال آن، فایل‌ها را با File Manager حذف کنید؛ یا اگر نام پوشه همین مثال است:

```bash
rm -- "$HOME/rb-index-diagnostic/diagnose.php" "$HOME/rb-index-diagnostic/result.json"
rmdir -- "$HOME/rb-index-diagnostic"
```

`rmdir` فقط پوشهٔ خالی را حذف می‌کند؛ اگر فایل دیگری در آن دارید، آن را پاک نمی‌کند. حذف ابزار، تغییری در صفحات یا تنظیمات سایت ایجاد نمی‌کند.

## راهنمای کوتاه خواندن خروجی

- `pages` شامل `hub`، `branding` و `campaign_360` است. در هرکدام `browser_ua` و `googlebot_ua_simulated_not_google` را مقایسه کنید. تفاوت `status`، `hops`، `raw_html`، `noindex_in_relevant_meta` یا canonical نشانهٔ قابل‌بررسی است، نه اثبات رفتار Googlebot واقعی؛ کش، ترتیب درخواست‌ها و محدودیت نرخ نیز می‌توانند پاسخ‌ها را تغییر دهند. `stop_reason` نشان می‌دهد ریدایرکت کجا و چرا متوقف شده است.
- `canonical_matches_requested_url` مقایسه با URL اولیه است؛ `canonical_matches_final_url` با پاسخ نهایی بعد از ریدایرکت مقایسه می‌کند. این دو فقط در صورت وجود یک canonical معتبر در `head` محاسبه می‌شوند. `canonical_outside_head_count` تعداد تگ‌های خارج از آن را جدا نشان می‌دهد. `null` یعنی ابزار نتوانسته یک canonical معتبر و یکتا برای مقایسه تعیین کند؛ `false` به بررسی نیاز دارد، اما خودکار علت ایندکس‌نشدن نیست. canonical انتخابی گوگل را از این خروجی نمی‌توان فهمید.
- `x_robots_tag_directive_words_unscoped` فقط واژه‌های شناخته‌شده را نشان می‌دهد و تشخیص نمی‌دهد هدر برای کدام ربات صادر شده است؛ وجود `noindex` در آن لزوماً به معنی منع Googlebot نیست. `noindex_in_relevant_meta` مربوط به متای `robots` یا `googlebot` در HTML خام است؛ در `robots_meta` محل آن با `in_head` مشخص است.
- `robots_txt.googlebot_rules_approximate` یک تخمین از قوانین فایل دریافت‌شده است؛ در موارد پیچیده با Live Test مقایسه شود. پاسخ HTML به‌جای robots با `response_looks_like_html` علامت می‌خورد و نتیجهٔ قوانین نامشخص می‌ماند. `page_sitemap.entries.*.present = false` فقط یعنی URL در **همین نقشهٔ کامل و قابل‌تحلیل** پیدا نشده است، نه در هیچ سایت‌مپ دیگری. مقدار `null` در نتایج یعنی نامشخص، نه تأیید سلامت یا خطا.
- اگر `content_type` موجود باشد و صراحتاً HTML یا XHTML نباشد، تحلیل `raw_html` انجام نمی‌شود. `links_to_targets` فقط تگ‌های `<a href>` در HTML خام و فقط مقصد همین سه صفحه را می‌شمارد؛ لینک ساخته‌شده با جاوااسکریپت یا نسخهٔ ذخیره‌شده نزد گوگل را نمی‌بیند. شمارش متن نیز تعداد کلمه یا محتوای قابل‌رؤیت نیست. `possible_challenge_marker_heuristic` فقط یک نشانهٔ احتمالی است و می‌تواند مثبت یا منفی کاذب باشد.
- `body_truncated` / `partial_body` یا `header_limit_reached` یعنی بخشی از پاسخ/هدرها بررسی نشده؛ نبودِ یک مورد در پاسخ ناقص قابل اتکا نیست. `curl_error_code` غیرصفر یعنی دریافت کامل نشده؛ برای نمونه `6` خطای نام دامنه، `7` اتصال، `28` زمان‌انتظار و `60` اعتبارسنجی گواهی است. این خطاها از **همان هاست** مشاهده شده‌اند و به‌تنهایی وضعیت شبکهٔ گوگل را ثابت نمی‌کنند. برای رفع خطا، بررسی کنید؛ اعتبارسنجی TLS را خاموش نکنید.

## بررسی مستقل تصویر ۳۶۰

در تصویر Live Test ارسالی، عنوان و مقدمهٔ تازه دیده می‌شوند و پس از آن فضای بنفش بزرگی وجود دارد. این تصویر به‌تنهایی ثابت نمی‌کند بخش‌های پایین حذف شده‌اند. در همان **View tested page → HTML** یکی از عنوان‌ها یا عبارت‌های مشخص پایین صفحه را جست‌وجو و با صفحهٔ واقعی مقایسه کنید؛ در **More info → Page resources / JavaScript console** خطاهای مرتبط را ببینید. پس از آن وضعیت هر سه URL را در **Google Index** پیگیری کنید؛ از آنجا که طبق اعلام شما درخواست هر سه URL بعد از اصلاح ثبت شده، درخواست تکراری خودکار لازم نیست. این بررسی‌ها نه علت قطعی و نه زمان ایندکس را تضمین می‌کنند.

**لینک‌های موجود سایت خدماتی به سایت شخصی در همه صفحات، طبق تصمیم کارفرما، بدون حذف یا تغییر حفظ می‌شوند.** این ابزار نیز آنها را تغییر نمی‌دهد.

## آزمون‌های توسعه (اختیاری؛ روی هاست لازم نیست)

در یک محیط توسعه دارای PHP CLI با cURL/DOM:

```bash
cd tools/royalbrand-index-diagnostic
php tests.php
python3 tests_http.py
```

آزمون دوم علاوه بر PHP به Python 3 و OpenSSL نیاز دارد. برای خودآزمایی یک گواهی و نسخهٔ تغییرمسیر‌یافتهٔ موقت در پوشهٔ موقت می‌سازد و فقط به سرور HTTPS محلی متصل می‌شود؛ فایل اصلی را تغییر نمی‌دهد. این آزمون‌ها شواهد رفتار واقعی هاست یا گوگل نیستند.
